# 参考文献异常检测 — 使用指南

本文档说明如何在本项目中完成**环境准备、一键全流程检测、分步命令行、Python API 与测试**。当前版本为 **0.5.0**，已实现架构中的模块一至五。

---

## 1. 能做什么

### 1.1 模块一：文本与结构解析

从投稿论文（PDF 或 Word）中自动抽取：

| 字段 | 说明 |
|------|------|
| `title` | 标题（启发式，取自首页靠前非标题行） |
| `abstract` | 摘要正文 |
| `keywords` | 关键词列表 |
| `body_text` | 正文（已去掉参考文献区） |
| `reference_section_text` | 参考文献区原文 |
| `citation_contexts` | 正文中的引用标记及上下文、所属章节 |

### 1.2 模块二：参考文献抽取与结构化

将参考文献区拆分为单条记录，并抽取：

| 字段 | 说明 |
|------|------|
| `ref_id` | 条目 ID，如 `R001` |
| `raw_text` | 原始参考文献字符串 |
| `title` / `authors` / `journal` / `year` / `doi` | 启发式字段（不查外部库） |
| `citation_markers` | 如 `[1]`、`[2-3]` |

### 1.3 模块三：DOI 与元数据校验

对每条参考文献的 DOI 查询 **Crossref**，并比对题名、期刊、年份：

| 输出 | 说明 |
|------|------|
| `doi_exists` | DOI 是否在 Crossref 存在 |
| `metadata_match_score` | 综合相似度（0–1） |
| `matched_title` / `matched_year` / `matched_journal` | 分项是否匹配 |
| `crossref_title` / `crossref_journal` | Crossref 返回的元数据 |
| `risk_flag` | 风险标记（见下文） |

**`risk_flag` 取值：**

| 值 | 含义 |
|----|------|
| `missing_doi` | 无 DOI，建议人工复核 |
| `doi_not_found` | DOI 在 Crossref 不存在 |
| `title_mismatch` | 题名明显不一致 |
| `year_mismatch` | 年份超出容差 |
| `journal_mismatch` | 期刊明显不一致 |
| `title_possible_mismatch` | 题名略有不一致，建议复核 |
| `api_error` | Crossref 请求失败 |
| `null` | 校验通过 |

### 1.4 模块四：撤稿文献检测

基于本地 **Retraction Watch** 索引，按参考文献 DOI 检测是否引用已撤稿原文或撤稿通知：

| 输出 | 说明 |
|------|------|
| `is_retracted` | 是否引用已被撤稿的**原文**（`original_doi` 命中） |
| `notice_doi` | 关联撤稿通知 DOI |
| `retraction_nature` / `retraction_date` / `reason` | 撤稿记录元数据 |
| `risk_flag` | 风险标记（见下文） |

**`risk_flag` 取值：**

| 值 | 含义 |
|----|------|
| `cites_retracted_work` | 引用了已被撤稿的原文（高风险，需人工复核） |
| `cites_retraction_notice` | 引用的是撤稿通知文献本身 |
| `null` | 本地索引未命中 |

**数据准备：** 生产环境需从 [Retraction Watch Database](https://retractionwatchdatabase.org/) 下载 CSV，构建本地 SQLite 索引（见 §5.4）。单元测试使用仓库内样例 CSV，**无需你提供完整库**。

### 1.5 模块五：风险汇总与报告

合并模块二至四结果，生成统一风险报告（不重新检测）：

| 输出 | 说明 |
|------|------|
| `risk_items` | 风险卡片列表（类型、等级、证据、建议操作） |
| `summary` | 统计：参考文献总数、DOI 命中/缺失/不一致、撤稿引用数等 |
| `retraction_check_skipped` | 撤稿检测是否被跳过 |

### 1.6 支持的文件与格式

**论文文件：**

- **PDF**（`.pdf`，PyMuPDF）
- **Word**（`.docx` / `.doc`，python-docx）

**正文引用标记：**

- 方括号编号：`[1]`、`[2-3]`、`[2, 3]`
- 作者-年份：`(Smith, 2020)`、`(Wang et al., 2021)`

**参考文献区标题（中英文）：** `References`、`Bibliography`、`参考文献`、`引用文献` 等。

**参考文献条目起始：** `[1]`、`1.` 等；支持跨行续行合并、换行打断的 DOI 修复。

## 4. 使用流程总览

### 4.0 推荐：一键检测（仅需论文文件）

```powershell
reference-run --file uploads\submission_001.pdf
```

- **stderr**：进度与各步可读摘要（`paper_id`、参考文献条数、风险项等）
- **stdout**：模块五汇总 JSON
- 可选：`--output reports\summary.json` 另存文件；`--save-intermediate reports\run_001\` 保存各步 JSON

若本地尚无撤稿索引，流水线会**自动跳过模块四**并在汇总中标注 `retraction_check_skipped`；也可显式 `--skip-retraction`。

```text
┌─────────────────┐
│  上传 PDF/Word   │
└────────┬────────┘
         ▼
┌─────────────────┐
│  reference-run   │  → summary.json（stdout）
└─────────────────┘
```

### 4.1 分步流水线（调试 / 集成）

```text
┌─────────────────┐
│  准备论文文件    │  PDF 或 Word
└────────┬────────┘
         ▼
┌─────────────────┐
│ reference-parse  │  → demo_parse.json
└────────┬────────┘
         ▼
┌─────────────────┐
│reference-extract │  → demo_refs.json
└────────┬────────┘
         ├──────────────────────────┐
         ▼                          ▼
┌─────────────────┐        ┌──────────────────────────┐
│reference-check-doi│      │reference-check-retraction│
│ → demo_doi_checks.json     │ → demo_retraction.json │
└────────┬────────┘        └────────────┬─────────────┘
         └──────────────┬─────────────┘
                        ▼
              ┌─────────────────┐
              │reference-summarize│ → summary.json
              └─────────────────┘
```

**首次使用模块四前（一次性或 CSV 更新后）：**

```powershell
# 将官方 CSV 放到 data\RetractionWatch.csv 后执行
reference-build-retraction-index --csv data\RetractionWatch.csv
```

**一键流水线示例（Windows PowerShell）：**

```powershell
$paper = "reference_anomaly_detection/tests/fixtures/sample_paper.pdf"
reference-parse --file $paper --output reports/demo_parse.json
reference-extract --from-parse reports/demo_parse.json --output reports/demo_refs.json
reference-check-doi --from-extract reports/demo_refs.json --output reports/demo_doi_checks.json
reference-check-retraction --from-extract reports/demo_refs.json --output reports/demo_retraction.json
reference-summarize --from-extract reports/demo_refs.json --from-doi reports/demo_doi_checks.json --from-retraction reports/demo_retraction.json --output reports/demo_summary.json
```

> **生产流程**：模块一**只需论文文件**；`paper_id` 在解析时自动生成并写入 JSON，后续模块从 JSON **继承**，无需用户填写（见 [§4.2](#42-paper_id-如何生成)）。

### 4.2 `paper_id` 如何生成

`paper_id` 是整条流水线的稿件主键，用于关联各步骤 JSON 与审稿系统数据库记录。

**标准生产流程（推荐）：**

```text
上传论文 → reference-parse（仅 --file）
         → 输出 JSON 含 paper_id（如 paper_a1b2c3d4e5f6）
         → 后端落库，后续任务携带该 ID
         → reference-extract / reference-check-doi 从 JSON 继承
```

| 步骤 | `paper_id` 来源 |
|------|----------------|
| **模块一** `reference-parse` | **自动生成**（`paper_` + 12 位十六进制），写入输出 JSON；stderr 打印 `paper_id: …` |
| **模块二** `--from-parse` | 从模块一 JSON **继承**（必填字段） |
| **模块三** `--from-extract` | 从模块二 JSON **继承** |
| **模块二** `--reference-text` | 仅独立调试：单独生成新 `paper_id` |

CLI **不提供** `--paper-id` 参数。若后端在解析前已有业务主键，可通过 **Python API** 传入（见 §6.1）。

## 5. 命令行使用

### 5.1 模块一：`reference-parse`

```bash
reference-parse --file <论文文件路径> [--output <输出.json>]
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--file` | 是 | 论文文件路径（唯一必填项） |
| `--file-type` | 否 | `pdf` / `docx` / `doc`；省略时按扩展名推断 |
| `--output` | 否 | JSON 保存路径；省略则打印到 stdout |

输出 JSON 中**必定包含**自动生成的 `paper_id`。

**示例：**

```powershell
reference-parse --file uploads\submission_001.pdf --output reports\parse.json
```

未安装脚本时：

```bash
python -m reference_anomaly_detection.main --file sample.pdf --output reports/parse.json
```

---

### 5.2 模块二：`reference-extract`

```bash
reference-extract \
  (--reference-text "<参考文献区文本>" | --from-parse <模块一.json>) \
  [--output <输出.json>]
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--from-parse` | 二选一（推荐） | 模块一 JSON；继承 `paper_id` 与 `reference_section_text` |
| `--reference-text` | 二选一 | 独立调试：仅传参考文献原文，会生成新 `paper_id` |
| `--output` | 否 | JSON 保存路径 |

**从模块一结果继续：**

```bash
reference-extract --from-parse reports/demo_parse.json --output reports/demo_refs.json
```

**直接传入文本：**

```bash
reference-extract --reference-text "[1] Smith J. Example. Journal A. 2020. doi:10.1000/test.1"
```

---

### 5.3 模块三：`reference-check-doi`

```bash
reference-check-doi --from-extract <模块二.json> [--output <输出.json>] [选项]
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--from-extract` | 是 | 模块二 JSON（含 `paper_id` 与 `references`） |
| `--output` | 否 | JSON 保存路径 |
| `--no-cache` | 否 | 禁用 Crossref SQLite 本地缓存 |
| `--mailto` | 否 | Crossref polite pool 联系邮箱（默认见代码） |

**示例：**

```bash
reference-check-doi --from-extract reports/demo_refs.json --output reports/demo_doi_checks.json
```

> Crossref 缓存默认目录：`~/.cache/reference-anomaly-detection/crossref_cache.sqlite`

---

### 5.4 构建撤稿索引：`reference-build-retraction-index`

```bash
reference-build-retraction-index --csv <RetractionWatch.csv> [--db <索引.sqlite>]
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--csv` | 是 | Retraction Watch 官方 CSV 路径 |
| `--db` | 否 | 输出 SQLite；默认 `reference_anomaly_detection/config/retraction_watch_index.sqlite` |

**是否需要提供 CSV？**

| 场景 | 说明 |
|------|------|
| 生产 / 全量检测 | **需要**：下载完整 CSV 放到如 `data/RetractionWatch.csv`，CSV 更新后需重新构建索引 |
| 开发 / `pytest` | **不需要**：使用 `tests/data/retraction_watch_sample.csv` |

```powershell
reference-build-retraction-index --csv data\RetractionWatch.csv
```

---

### 5.5 模块四：`reference-check-retraction`

```bash
reference-check-retraction --from-extract <模块二.json> [--output <输出.json>] [--db <索引.sqlite>]
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--from-extract` | 是 | 模块二 JSON（含 `paper_id` 与 `references`） |
| `--output` | 否 | JSON 保存路径 |
| `--db` | 否 | 撤稿索引路径；省略时使用默认路径 |

**示例：**

```bash
reference-check-retraction --from-extract reports/demo_refs.json --output reports/demo_retraction.json
```

索引不存在时会提示先运行 `reference-build-retraction-index`。

### 5.6 模块五：`reference-summarize`

```bash
reference-summarize \
  --from-extract <模块二.json> \
  --from-doi <模块三.json> \
  [--from-retraction <模块四.json>] \
  [--output <汇总.json>]
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--from-extract` | 是 | 模块二 JSON |
| `--from-doi` | 是 | 模块三 JSON |
| `--from-retraction` | 否 | 模块四 JSON；省略则视为未执行撤稿检测 |
| `--output` | 否 | 汇总 JSON 路径；省略则打印到 stdout |

---

### 5.7 一键全流程：`reference-run`

```bash
reference-run --file <论文.pdf> [--output <汇总.json>] [选项]
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `--file` | 是 | 论文 PDF 或 Word |
| `--output` | 否 | 另存汇总 JSON（仍会打印到 stdout） |
| `--save-intermediate` | 否 | 目录：写入 parse / extract / doi_checks / retraction_checks / summary |
| `--skip-retraction` | 否 | 跳过撤稿检测 |
| `--db` | 否 | 撤稿索引 SQLite 路径 |
| `--no-cache` | 否 | 禁用 Crossref 缓存 |
| `--mailto` | 否 | Crossref 联系邮箱 |

**示例：**

```powershell
reference-run --file uploads\submission_001.pdf --output reports\summary.json
```

## 6. Python API 调用

### 6.1 模块一：解析论文

```python
from pathlib import Path

from reference_anomaly_detection.models.schemas import PaperParseInput
from reference_anomaly_detection.parsers.document_parser import DocumentParser

# 生产用法：仅传文件，paper_id 自动生成
result = DocumentParser().parse(
    PaperParseInput(file_path=Path("uploads/submission_001.pdf"))
)
print(result.paper_id)
print(result.reference_section_text)

# 若后端在解析前已分配业务主键，可显式传入（可选）
result = DocumentParser().parse(
    PaperParseInput(
        file_path=Path("uploads/submission_001.pdf"),
        paper_id="submission_001",
    )
)
```

### 6.2 模块二：结构化参考文献

```python
from reference_anomaly_detection.models.schemas import ReferenceExtractInput
from reference_anomaly_detection.parsers.reference_extractor import ReferenceExtractor

extracted = ReferenceExtractor().extract(
    ReferenceExtractInput(
        paper_id=result.paper_id,
        reference_section_text=result.reference_section_text,
    )
)
for ref in extracted.references:
    print(ref.ref_id, ref.doi, ref.title)
```

### 6.3 模块三：DOI 校验

```python
from reference_anomaly_detection.checkers.doi_metadata_checker import DoiMetadataChecker
from reference_anomaly_detection.models.schemas import DoiCheckInput

checks = DoiMetadataChecker().check(
    DoiCheckInput(
        paper_id=extracted.paper_id,
        references=extracted.references,
    )
)
for item in checks.doi_checks:
    print(item.ref_id, item.risk_flag, item.metadata_match_score)
```

### 6.4 模块四：撤稿检测

```python
from reference_anomaly_detection.checkers.retraction_checker import RetractionChecker
from reference_anomaly_detection.models.schemas import RetractionCheckInput
from reference_anomaly_detection.services.retraction_watch_index import RetractionWatchIndex

index = RetractionWatchIndex(RetractionWatchIndex.default_db_path())
retraction = RetractionChecker(index).check(
    RetractionCheckInput(
        paper_id=extracted.paper_id,
        references=extracted.references,
    )
)
for item in retraction.retraction_checks:
    print(item.ref_id, item.risk_flag, item.is_retracted)
```

构建索引：

```python
RetractionWatchIndex.build_from_csv("data/RetractionWatch.csv")
```

### 6.5 模块五：风险汇总

```python
from reference_anomaly_detection.models.schemas import RiskSummaryInput
from reference_anomaly_detection.reports.report_builder import RiskReportBuilder

report = RiskReportBuilder().build(
    RiskSummaryInput(
        paper_id=extracted.paper_id,
        references=extracted.references,
        doi_checks=checks.doi_checks,
        retraction_checks=retraction.retraction_checks,
    ),
)
print(report.summary, report.risk_items)
```

## 8. 配置文件

配置位于包内 `reference_anomaly_detection/config/`：

| 文件 | 用途 |
|------|------|
| `thresholds.yaml` | 模块三：题名/期刊相似度阈值、年份容差、API 超时与重试 |
| `journal_aliases.yaml` | 模块三：期刊缩写与全称映射 |
| `retraction.yaml` | 模块四：默认撤稿 SQLite 索引路径 |

安装后随包分发；本地开发可直接编辑上述文件，无需重装。主要阈值说明：

```yaml
doi_title_match_high_risk_threshold: 0.6   # 低于此值 → title_mismatch
doi_title_match_medium_risk_threshold: 0.8   # 匹配判定及格线
doi_journal_match_threshold: 0.75
doi_year_tolerance: 1                        # 年份允许偏差
api_timeout_seconds: 10
cache_enabled: true
```

## 10. 嵌入审稿系统

推荐异步任务链（见 [`architecture.md`](../architecture.md)）：

```text
用户上传论文
  → 保存文件
  → reference-parse          （模块一）
  → reference-extract        （模块二）
  → reference-check-doi      （模块三）
  → reference-check-retraction （模块四，本地索引）
  → reference-summarize / reference-run （模块五）
  → 后端写入 risk_items → 报告页展示
```

集成建议：

1. 用户上传后调用 `reference-parse --file …`，将返回的 `paper_id` 写入稿件表；
2. 部署时定期更新 Retraction Watch CSV 并重建索引；
3. 后续异步任务只传 JSON 文件路径或内容，**不再生成新** `paper_id`；
4. `citation_contexts` 保留，供撤稿引用是否在正文说明等扩展；
5. 对 `doi_checks` / `retraction_checks` 中 `risk_flag` 非空的条目生成风险卡片；
6. 配置 `mailto` 为机构联系邮箱（Crossref polite pool）。

## 11. 常见问题

### Q1：提示「论文文件不存在」

检查 `--file` 路径；Windows 下可用正斜杠或反斜杠。

### Q2：`reference_section_text` 为 null

PDF 未识别到参考文献标题时会出现。查看 `body_text` 是否仍含参考文献，必要时扩展 `document_parser.py` 中的 `REFERENCE_HEADING_PATTERNS`。

### Q3：参考文献字段（题名/作者）不准确

模块二为规则抽取，复杂版式、中文专著等可能偏差；DOI 抽取相对更可靠。模块三主要依赖 DOI 与 Crossref 元数据比对。

### Q4：`reference-check-doi` 很慢或失败

- 首次查询会访问 Crossref，之后走本地 SQLite 缓存；
- 检查网络与防火墙；
- 失败项 `risk_flag` 为 `api_error`，可重试或加 `--no-cache` 排除缓存问题。

### Q5：命令找不到

确认已 `pip install -e ".[dev]"` 且虚拟环境已激活。等价模块调用：

```bash
python -m reference_anomaly_detection.main
python -m reference_anomaly_detection.extract_main
python -m reference_anomaly_detection.doi_check_main
python -m reference_anomaly_detection.retraction_check_main
```

### Q6：提示「撤稿索引不存在」

先下载 Retraction Watch CSV，再执行：

```bash
reference-build-retraction-index --csv data/RetractionWatch.csv
```

开发测试可用样例：

```bash
reference-build-retraction-index --csv reference_anomaly_detection/tests/data/retraction_watch_sample.csv --db reference_anomaly_detection/config/retraction_watch_index.sqlite
```

### Q7：`.doc` 文件

CLI 将 `doc` 视为 `docx`；老旧 `.doc` 建议先转为 `.docx`。
